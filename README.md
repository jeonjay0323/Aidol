# Lukids

> AI 컴패니언과 얼굴을 보고 목소리로 대화하는 서비스

프롬프트로 아이돌을 만들고, 영상통화로 대화하고, 관계를 쌓는다.
기존 캐릭터챗이 1:1 텍스트에 머무는 것과 달리 **얼굴과 목소리**를 중심에 둔다.

> "실제 아이돌은 나를 모르지만, 이 아이돌은 나를 안다"

선택하는 경험이 아니라 **선택받는** 경험. AI 아이돌이 먼저 통화를 걸어온다.

---

## 1. Understand — 무엇을 확인하려는가

서비스를 크게 벌였다가 인터뷰에서 문제가 드러나 한 번 닫았다.
지금은 **쪼개서 하나씩 검증**하는 중이고, 그 첫 조각이 이 저장소다.

> 어떤 때에 사람들이 AI 컴패니언에 **소유감**과 **애정**을 갖는가.
> 그리고 **다인 참여**가 여기에 어떤 영향을 미치는가.

기존 AI 컴패니언은 대부분 1:1이다. 다인 참여가 애착을 키우는지 깎는지는
검증된 바가 적다. 양방향으로 작용할 수 있다고 보고 두 가설을 모두 열어 뒀다.

| 키울 수 있는 쪽 | 깎을 수 있는 쪽 |
|---|---|
| 사회적 실재감 — 남이 내 컴패니언과 대화하면 "있는 존재"가 된다 | 사적 친밀감 훼손 — 1:1의 은밀함이 깨진다 |
| 과시 — 소유물은 보여줄 때 가치가 오른다 | 희소성 훼손 — 남도 비슷한 것을 가진다 |
| 관계 확장 — 내 컴패니언이 남의 컴패니언과 얽힌다 | 통제 상실 — 남 앞에서 이상하게 굴 수 있다 |

→ [실험 배경 문서](docs/실험%20배경%20—%20다인%20참여형%20컴패니언.md)

## 2. Decide — 왜 카드인가

포켓몬 GO는 디지털 콘텐츠가 사람을 **물리적 장소로 불러 모으는 것**을 보여줬고,
포켓몬 카드·프리파라는 사람들이 **소유하는 실물에 디지털이 붙어 있는 것**을 즐긴다는 것을 보여줬다.

둘을 합치면 **"손에 쥔 카드가 디지털 존재를 불러온다"** 가 된다.

카드를 고른 또 하나의 이유는 **측정**이다.
디지털 소유감은 재기 어렵다 — 계정에 남아 있다고 애착이 있는 것은 아니다.
카드는 가져가거나 두고 간다. 전시가 끝난 뒤 **남은 카드 수**를 세는 것만으로 1차 지표가 나온다.

## 3. Prototype — 어떻게 만들었나

```
Aidol/
├── docs/                          기획 · 실험 문서
│   ├── 실험 배경 — 다인 참여형 컴패니언.md
│   ├── 프로젝트 기획안.md
│   ├── 프로젝트 진행 상황.md
│   └── features/                  기능 명세
│       ├── AI 개인 영상 통화.md
│       ├── AI 다자간 통화.md
│       └── 유저 취향 분석.md
├── services/                      배포되는 것
│   └── exhibition-card/           전시용 피지컬 카드 · 통화 · 멀티콜
├── tools/                         사람이 돌리는 것
│   └── image-generator/           카드 얼굴 이미지 생성
└── archive/                       대체된 프로토타입
    ├── solo-call/                 1:1 통화 원형
    └── multi-call/                대사 사전생성 방식
```

디렉터리는 **실행 주체**로 나눴다. `services/`는 서버가 돌리는 것,
`tools/`는 사람이 손으로 돌리는 것이다.

### `services/exhibition-card` — 전시용 피지컬 카드

카드를 스캔하면 그 아이돌과 영상통화가 시작된다.
다른 카드를 초대하면 여럿이 함께 대화한다. Cloud Run + Firestore 로 배포되어 있다.
→ [상세 문서](services/exhibition-card/README.md)

### `tools/image-generator` — 카드 얼굴 이미지

카드에 들어갈 인물 이미지를 만든다. Simli 얼굴 등록에는 정면 · 1024×1024 정사각형이 필요하다.

### `archive/` — 대체된 프로토타입

`solo-call`(Gemini Live + Simli 1:1 통화)의 구조는 exhibition-card 로 흡수됐다.
`multi-call`은 대사를 미리 만들어 재생하는 다른 기능이라 재사용하지 않았다.
지우지 않고 남겨 과정을 보이게 했다.
→ [archive/README.md](archive/README.md)

## 4. 막힌 곳과 푼 방법

기능을 빼는 대신 **막힌 조건을 그대로 두고 경험이 끊기지 않는 쪽**으로 설계를 바꿨다.

| 막힌 것 | 푼 방법 |
|---|---|
| 얼굴 등록에 최대 8시간이 걸리는데 카드는 현장에서 바로 나가야 한다 | 등록 상태(`face_status`)를 화면과 통화 방식에 직접 연결. 준비되면 영상통화, 아직이면 "얼굴을 만드는 중"이라 말하고 음성 통화. **등록이 실패해도 카드는 이미 손에 있고 대화는 된다** |
| AI가 말을 끊고 들어온다 | 모델의 자동 발화감지를 끄고 브라우저가 판단 — 음량 임계값 0.02 · 침묵 1초. 첫 음절이 잘리는 문제는 말하기 직전 구간(preroll)을 함께 보내 해결 |
| 여럿이 동시에 말하면 컴패니언들이 겹쳐 답한다 | 서버가 매 턴 **답할 한 명**을 정하고, 나머지에게는 같은 내용을 텍스트로만 주입해 맥락은 알되 말은 하지 않게 함. 사람이 얼굴을 탭해 직접 지목할 수도 있다 |
| 아바타가 늦게 뜨거나 립싱크가 빠진다 | 응답 음성을 스피커와 아바타로 동시에 흘리도록 경로 변경 |

### 아직 못 푼 것 — 멀티콜의 다자 립싱크

Simli 무료 플랜이 동시 연결 1개로 묶여 있다.
지금은 **말하는 한 명만 영상**, 나머지는 정지 화면이다.
유료 전환이나 대체 엔진이 필요하고, 전시 전까지 결정해야 한다.

## 5. Test — 무엇을 어떻게 잴 것인가

재방문율을 중심 지표로 두고, **소유감과 애정은 합치지 않고 따로** 본다.

| 지표 | 측정 방법 | 보려는 것 |
|---|---|---|
| 카드 반출 | (발급 수 − 남은 카드) ÷ 발급 수 | 소유 |
| 다음 날 재스캔 | 같은 카드의 첫 스캔과 이후 스캔, 날을 넘긴 재방문을 따로 집계 | 애정 |
| 통화 시간 · 턴 수 | 통화 시작·종료 로그 | 몰입 · 흥미 |
| 멀티콜 · 초대 | 멀티콜 참여, 로비 입장 | 다인 노출 · 확장 의지 |

멀티콜을 한 번이라도 한 카드는 **다인**, 1:1만 한 카드는 **개인**으로 자동 분류해
두 코호트의 재방문율 **차이의 방향**을 본다.
15초 이상 통화한 사람에게는 두 문항을 묻는다 — "실제로 존재하는 것 같았나요?" · "또 이야기하고 싶나요?"

## 6. 결론

아직 데이터가 없다. 지금 시점에서 말할 수 있는 것만 적는다.

- **측정할 수 있는 형태로 옮겼다** — "소유감과 애정"을 카드 반출 · 재스캔 · 통화 시간 · 초대라는 네 개의 행동으로 바꿨다. 말로 묻는 대신 행동으로 세기 위해서다.
- **양쪽 가설을 모두 열어 뒀다** — 다인 참여가 애착을 키울지 깎을지 정하지 않고 차이의 방향을 본다.
- **제약을 없애는 대신 설계로 흡수했다** — 8시간 등록 지연도, 겹쳐 말하는 문제도 기능을 빼지 않고 풀었다.

로그는 "무엇을 했는지"만 알려준다. **왜 다시 찍었는지는 전시 후 인터뷰로 따로 묻는다.**

## 실행

각 서비스 디렉터리의 README 또는 `config.py`를 참고한다.
API 키는 `.env`로 관리하며 저장소에 포함하지 않는다.

| 환경변수 | 용도 |
|---|---|
| `SIMLI_API_KEY`, `SIMLI_FACE_ID` | 아바타 얼굴 · 립싱크 |
| `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` | TTS 음성 |
| `GOOGLE_CLOUD_PROJECT`, `VERTEX_LOCATION` | Gemini (Vertex AI) |
